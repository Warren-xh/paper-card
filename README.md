# 文献卡片

读一篇，记一张；回头看，一眼想起。

一个记论文笔记的个人网站，免费托管在 GitHub Pages，不需要服务器。在任何设备上输入密码就能写「论文卡片」，点发布后网站大约 1 分钟自动更新。目的是解决「读完一篇文献跟没读一样」：每张卡片最醒目的是一句话总结，回看时一眼就能想起来；读完的卡片还会按间隔提醒你回顾。

网址：<https://warren-xh.github.io/paper-card/>

## 怎么用

**写一张卡片**：首页点「写一张新卡片」。先填基本信息，可以顺手上传论文 PDF（见下文）。编辑页分四个阶段：

1. **读之前**：一行字写下为什么读这篇、想从里面得到什么。
2. **边读边记**：只打标记，不写长句。四种符号：
   `?` 没看懂 ｜ `!` 关键结论 ｜ `★` 可以借鉴 ｜ `×` 有问题。
   另有 `✎` 普通笔记，记不属于以上四类的内容。
   选符号、写几个字，回车就记下一条，接着记下一条。页码默认从 1 开始，翻页时点 ＋（或按 ↑ ↓），也可以直接改数字或清空。
   用中文输入法时，回车只用来确认选字，不会误记下一条。
   觉得某一条还没解决，记下之前勾上输入框旁的「待解决」（默认不勾，每记一条自动取消）；已经记下的标记也可以在列表里随时勾上或取消。
3. **初步解决问题**：只列出勾了「待解决」的标记，读完第一遍后给它们写答案，没弄懂的留空；另有一栏「其他初步弄懂的」。取消「待解决」后答案仍然保留，但不显示、也不计入。
4. **读完 · 合上论文再写**：写的时候不看原文，写不出来的那栏就是没懂的地方。
   - ① 一句话（最重要）：点句式按钮「用【什么方法】解决了【什么问题】，结果【比谁好多少】」，直接打字填空，按 Tab 跳到下一个空
   - ② 痛点　③ 核心想法（可插图）　④ 怎么证明的（数据集 / 对比对象 / 关键数字）
   - ⑤ 疑问 / 局限：「带入阅读时的 ? 和 ×」一键把读时的标记带进来（已经写了答案的不带）
   - ⑥ 和我有什么关系：「带入 ★」
   - ⑦ 关联：搜索并选中已有的其他卡片，再写一段说明区别。关联只在这张卡片里记下对方的编号（几十个字节），不会新建卡片；对方卡片上会自动显示「被这些卡片关联」

另有自由笔记，支持 Markdown、公式 `$…$` 和图片。标记、答案和各栏文字都可以加粗、斜体：选中文字点 **B** / *I*，或按 ⌘/Ctrl + B、⌘/Ctrl + I。编辑栏底部会提示「卡片 n/7，还差 ②⑤」。卡片页只显示写了内容的栏目。

**论文 PDF**：编辑页的「论文 PDF」点「上传 PDF」（最大 50 MB），文件马上存进仓库的 `papers/` 文件夹；之后卡片页会出现「下载论文 PDF」。换文件或移除后再发布，仓库里的旧文件会一起删掉。注意仓库是公开的，知道链接的人都能下载，付费期刊的论文请留意版权。刚上传的文件要等网站更新（约 1 分钟）后才能下载。

**发布**：点「发布」，这台设备第一次发布时要输入密码。写的内容会自动存为本机草稿，没发布也不会丢。

**首页**：卡片网格，每张卡片上最大的字就是「一句话」；右上角的「待解决 2」表示还有 2 条待解决的标记没写答案，`PDF` 表示附了论文原文。顶部提示今天有几张该回顾，可以按状态（在读 / 读完 / 有待解决的）、标签、项目筛选，也可以搜索。

**回忆模式**：打开一张卡片，点「回忆模式」，内容会被模糊遮住。先自己回想每一栏，再逐栏点「揭晓」对照。

**回顾**：卡片标成「读完」后，第二天开始提醒（导航栏「回顾」旁的数字）。回顾时先只显示标题，试着用一句话说出它用什么方法、解决了什么问题、结果如何（可以写下来，不会保存），再点「揭晓答案」对照，然后选：

| 选项 | 下次回顾 |
| --- | --- |
| 忘了 | 明天，间隔从头开始 |
| 有点模糊 | 3 天后 |
| 想起来了 | 间隔按 1 → 7 → 30 → 90 → 180 天递增 |

回顾结果保存在卡片里，卡片页底部能看到回顾记录。

**示例卡片**：仓库里自带一张 BERT 的示例卡片（标签「示例」），看完在「编辑 → 删除」即可。

## 实操记录

顶栏左上角的「文献 | 实操」可以切换模式。「实操」用来记写代码、跑实验、做练习的过程，比论文卡片轻：

1. **开始前**：一行目标。
2. **过程中**：随手记，每条自动带时间。符号：`▶` 操作 ｜ `✗` 报错 ｜ `✓` 成功 ｜ `?` 疑问 ｜ `✎` 笔记。卡住的问题勾「待解决」。
3. **做完后**：结论（一句话）、问题与解决（列出勾了「待解决」的记录，写怎么解决的）、关键代码 / 命令（直接粘贴，保留缩进，Tab 键缩进）、结果（可插图）、下次要做、相关论文（选论文卡片，卡片页会显示「相关实操记录」）。

**上传代码**：编辑页的「代码文件」可以「上传文件」（多选）或「上传文件夹」（保留目录结构），文件马上存进仓库的 `code/<记录编号>/`。记录页会列出所有文件：文本文件可以直接「查看」（`.ipynb` 显示成单元格代码），所有文件都能「下载」，也能跳到 GitHub 上看整个文件夹。同名文件再传会覆盖；移除文件或删除记录后再保存，仓库里的文件也会删掉。仓库是公开的，上传时会自动跳过 `.env`、密钥文件（`.pem`、`id_rsa` 等）、`node_modules`、`.git`、`__pycache__`、虚拟环境等；单个文件最大 25 MB，一次最多 200 个文件、共 100 MB。

列表按月份分组，可以搜索（包括命令、报错内容和文件名）、按状态 / 项目 / 标签筛选。打开网站时会回到你上次用的模式。密码和授权与论文卡片共用。

## 思维导图

顶栏「文献 | 实操 | 导图」切到「导图」。可以建多张导图，每张从中心主题出发加分支。分支有三种，一眼能分清：

- **文字**：普通的分支，按所在主干的颜色显示。
- **论文**：带蓝色「论文」标签和左侧色条，显示卡片标题和「读完 / 在读」。
- **实操**：带绿色「实操」标签和左侧色条，显示记录标题和「完成 / 进行中」。

论文和实操分支显示的是卡片 / 记录的**最新标题**；原卡片删除后，分支会标成「已删除」。

**浏览模式**（默认）：拖动空白处移动画布，滚轮（或触控板、双指）缩放；点论文、实操分支直接打开对应的卡片或记录，返回后导图停在原来的位置；点有子分支的文字分支或旁边的 −/+ 可以折叠展开；「只看主干」「全部展开」「适应」一键调整；「复制大纲」把整张图复制成缩进列表。

**编辑模式**：点分支选中，在右侧（手机上在下方）面板里改文字、选颜色、写备注（浏览时悬停可见）、上移下移、删除。「给…加分支」可以输入文字回车添加，也可以切到「论文」「实操」搜索后点一下添加（默认只列读完的论文、完成的记录，已在图中的会标出来）。把一个分支拖到另一个分支上就移到它下面。快捷键：Tab 加子分支、Enter 加同级、Delete 删除、方向键切换选中、⌘/Ctrl + Z 撤销、⌘/Ctrl + Shift + Z 重做。改完点「保存」；没保存的修改会存在本机，下次打开会恢复。

## 密码是怎么工作的

网站本身是静态页面，修改内容需要 GitHub 的写入权限。第一次设置时：

1. 在 GitHub 生成一个**只授权本仓库**的细粒度令牌（fine-grained token，Contents 读写权限）。
2. 在网站「设置 → 第一次设置」粘贴令牌并设一个密码。

令牌在浏览器里用你的密码加密（PBKDF2 60 万次 + AES-256-GCM），只把加密结果保存为 `data/vault.json`。之后在任何设备输入密码，浏览器就能在本地解开令牌，直接提交到仓库。

- 密码不会被发送或保存到任何地方，忘了只能重新设置（用新令牌）。
- 加密文件在公开仓库里，所以密码不要太简单，也不要和其他账号共用。
- 令牌只能改这一个仓库；万一泄露，到 GitHub 删除令牌，再回到网站重新设置即可。
- 令牌最长有效期一年。过期后在「设置 → 修改密码 / 更换令牌」里换新的。
- 解锁后默认只在当前浏览器标签页有效，闲置 30 分钟自动锁定；勾选「记住我 30 天」则在这台设备上保持 30 天。

## 数据在哪

| 路径 | 内容 |
| --- | --- |
| `data/cards/<id>.json` | 一篇论文一张卡片，id 形如 `20261020-bert-x7k2` |
| `data/index.json` | 所有卡片的摘要，用于首页、搜索和回顾队列 |
| `data/logs/<id>.json` | 一条实操记录 |
| `data/logs-index.json` | 所有实操记录的摘要 |
| `code/<记录编号>/` | 实操记录里上传的代码文件 |
| `data/maps/<id>.json` | 一张思维导图 |
| `data/maps-index.json` | 所有导图的摘要 |
| `data/site.json` | 网站标题、副标题、仓库名 |
| `data/vault.json` | 加密后的编辑授权 |
| `uploads/` | 卡片里插入的图片（浏览器里先压缩再上传） |
| `papers/` | 上传的论文 PDF |

每次发布都是一次 Git 提交（卡片、索引和图片一起提交），误删或改错都能从 GitHub 历史里找回。如果两台设备同时发布，会自动在最新版本上重试。「设置」页也可以一键下载全部卡片（Markdown 或 JSON）。

## 本地开发

纯静态网站，没有构建步骤，也没有任何依赖。Node.js 18 以上只用于测试和本地预览。

```sh
npm test              # 单元测试
npm run dev           # 预览 http://127.0.0.1:4180
npm run mock          # 带模拟 GitHub 的预览，打开 http://127.0.0.1:4180/?mock
npm run reindex       # 手动改过 data/cards/ 后，用它重建 data/index.json
```

模拟模式下可以完整试用首次设置、发布、回顾和删除（令牌随便填一个 `github_pat_` 开头、足够长的字符串），所有修改只存在内存里，关掉服务就消失，不会碰到真实仓库。

代码结构：

| 文件 | 作用 |
| --- | --- |
| `index.html`、`css/style.css` | 页面和样式（明暗主题） |
| `js/app.mjs` | 页面逻辑：首页、卡片页、编辑、回顾、设置 |
| `js/model.mjs` | 卡片数据、七栏进度、回顾间隔、搜索、导出 |
| `js/lab.mjs`、`js/lab-views.mjs` | 实操记录的数据和页面 |
| `js/mindmap.mjs`、`js/map-views.mjs` | 思维导图的数据、自动排版和页面 |
| `js/github.mjs` | 通过 Git Data API 一次提交多个文件，冲突自动重试 |
| `js/vault.mjs` | 令牌的加密和解密 |
| `js/markdown.mjs` | 安全的 Markdown 渲染 |
| `scripts/serve.mjs` | 本地预览服务器（含 `--mock` 模拟 GitHub） |

和 [research-log](https://github.com/Warren-xh/research-log) 用的是同一套架构。
